# 09 项目执行与技术美术规范

> 状态：建议执行基线；首版平台与性能档位需在 MVP 开始前确认。本文描述目标与验收方法，不声称实现已完成。

## 1. 项目目标

建立可供游戏特效团队日常使用的 2D/2.5D 程序化效果编辑器。用户应能以图形节点编辑、时间预览和可复用资产制作 Sprite、粒子、拖尾及简单模拟效果；核心效果可离线/确定性预览、可迭代并可交付到游戏项目。

核心成功标准：一名特效师能从空白项目创建一个效果，调整参数/动画，在目标帧率下预览，保存并导出到已确认的首发目标环境；打开导出结果后视觉和时序与编辑器验收结果一致。

## 2. 首版边界

### P0：贯通手动与 AI 两条创作路径

- 单一明确的首发桌面平台、渲染 API 和游戏引擎/运行时集成目标（待决策）。
- 项目保存/重开、稳定 ID、基础 Undo/Redo 与资源引用。
- 强类型节点图：Sprite/贴图输入、颜色与数值参数、简单组合、Particle/Trail、动画曲线、基础排序和 2D 预览。
- 基础 CPU 参考执行；如首发采用 GPU 执行，须与 CPU 结果建立容差测试。
- 至少一种可集成导出格式；定义颜色空间、Alpha 约定、帧率、Pivot、Bounds、事件和资源依赖。
- 可复现示例工程、核心节点说明、错误诊断和自动化验收。
- 手动编辑与基础 AI 编辑：自然语言创建/修改效果、解释/诊断、受限 Graph/Parameter Patch、校验、预览、人工确认、原子应用、Undo、Revision 冲突处理；AI 与手动编辑共用 Project Graph。详细契约见文档 11。

### P1：验证后扩展

- Simulation Zone、固定时间步缓存/Bake、Field/Attribute 和沿路径实例化。
- GPU 性能优化、更多合成节点、图组/模板管理、性能分析。
- 高级视觉迭代、优化 Agent、多 Provider 智能路由和批量工作流，以及更多格式、插件 SDK。

### 暂不纳入首个可用版本

通用 3D DCC、完整 NLE、复杂流体/布料、任意代码节点、自动访问外部服务、多人实时协作，以及尚未选定的多引擎通用导出。不得以实现这些能力为理由延迟 P0 生产路径。

## 3. 阶段门禁

| 阶段 | 交付物 | 出口条件 |
|---|---|---|
| A. 产品与平台验证 | 用户任务清单、平台决策、效果参考板、最小交互原型、数据契约草案 | 首发用户、目标硬件、运行时/引擎、画布分辨率、帧率与导出通道均有负责人确认 |
| B. 垂直切片 | 项目打开/保存、最小图、手动参数编辑、AI 受限参数修改 Patch、实时预览、一次导出 | 同一效果可手动编辑，也可 AI 修改并经预览/确认/Undo；修改后可继续手工编辑、保存/重开和目标端验证；无阻塞数据丢失/崩溃问题 |
| C. 可用核心 | Undo/Redo、节点诊断、动画、基础粒子与拖尾、基础 AI 创建/修改/解释、预览事务、资源管理、示例和测试 | P0 验收全部通过；Manual/AI 往返编辑、Revision 冲突、取消/失败回滚及项目往返/图编译/导出回归通过 |
| D. 高级模拟与性能 | 固定步长模拟、Bake/Reset、缓存策略、CPU/GPU 对照与性能剖析 | 确定性、内存和帧时间符合确认的目标档位；长时间/时间跳转测试通过 |
| E. 高级 AI 与扩展 | 多 Provider/本地路由、视觉迭代、优化 Agent、批量工作流、插件/更多导出 | AI 断开不影响手动流程；高级自动化通过独立权限/事务测试 |

阶段 B/C 的可用核心必须覆盖基础 AI 创建/修改，不得等待阶段 E；详细 AI 闭环、Revision 冲突与失败测试见[双模编辑规格](11_手动与AI双模编辑规格.md)。

每个阶段均需产物链接、测试结果、已知问题和签收人；门禁未通过时不得把后续能力标记为已交付。

## 4. 技术美术内容规范

### 效果资产

每个示例效果至少提供：源工程/节点图、贴图源文件或生成方式、目标平台/画布尺寸、时间范围与 FPS、背景与色彩空间、Pivot/Bounds、关键帧截图或视频、参数说明、导出产物和复现步骤。贴图使用透明通道时，明确 Straight 或 Premultiplied Alpha；发光/叠加效果记录预乘约定和颜色空间。

建议按 `效果族/效果名/版本/` 组织源工程、纹理、导出和预览；命名使用稳定 ASCII 标识，展示名称可中文。贴图记录尺寸、格式、压缩、过滤、Wrap、Mip、通道含义和是否需要读写；不得只交付打包后的图集而丢失可编辑源资产。

### 节点与参数

节点 Descriptor 至少包含稳定 `type_id`、版本、分类、用途、输入/输出 Socket、参数默认值/范围/单位、动画能力、CPU/GPU 支持、确定性、资源成本提示、诊断文本和最小示例。Socket 类型变化须有版本迁移或明确破坏性升级说明。单位统一：时间用秒、角度文档化度或弧度并全局一致、颜色说明工作空间、尺寸说明归一化或像素单位。

### 视觉验收

验收包需定义参考时间点、播放速率、摄像机/画布、背景和质量档位。比较应包含起始、中间、结束帧及重要事件；涉及随机效果时固定 Seed。视觉差异需归类为预期随机性、采样容差、颜色/Alpha 偏差、排序/时序偏差或功能错误。最终以导出目标端检查为准，不能只看编辑器截图。

## 5. 性能、质量与验证约定

首发设备与数值预算待决策，不使用未经测量的宣传数字。基线建立后，对每个代表场景记录设备/驱动、分辨率、粒子/顶点数量、预热方式、采样帧数、P50/P95 帧时间、峰值显存/内存和质量档位。优化前后需用相同场景与脚本对比。

最小验证矩阵：

- 项目：新建、保存/关闭/重开、资源丢失提示、路径移动、备份/恢复。
- Graph：类型匹配/不匹配、缺失节点、环路、断连输出、稳定排序、序列化往返。
- 运行时：固定 Seed、重复运行、时间跳转、暂停/恢复、目标帧率、CPU/GPU 容差。
- 视觉：Alpha、颜色空间、排序、裁切、Pivot、Bounds、纹理过滤与目标端一致性。
- 导出：依赖齐全、帧率/时长准确、透明通道正确、重复导出可比较。
- AI（P0）：过期 Revision、拒绝/取消、超时、无效 Patch、部分失败、撤销、未授权 Provider 和断网；手动编辑仍可用，提交无半成品。

## 6. 设计与工程决策记录

下列事项应在阶段 A 评审并记录决策，不应由路线图隐式决定：

| 决策 | 影响 | 推荐确认时间 |
|---|---|---|
| 首发操作系统与最低硬件/GPU | 渲染后端、CI、性能预算 | 阶段 A |
| 编辑器 UI 框架与部署方式（BUI Rust 为首选原型） | 节点画布、wgpu 视口合成、分发许可证、打包、输入法/无障碍 | 阶段 A 原型及许可证评审后；见文档 10 |
| 首个游戏运行时/集成方式 | 导出格式、坐标/材质/资源语义 | 阶段 A |
| 首版 P0 效果族与代表验收场景 | 节点优先级、视觉资产准备 | 阶段 A |
| CPU/GPU 目标与质量降级策略 | 实现复杂度、性能验收 | 阶段 A/B |
| 项目格式迁移与缓存兼容策略 | 长期资产可维护性 | 垂直切片前 |
| AI Provider、凭证/本地推理方案、成本与隐私策略 | 基础 AI 是首版要求；需确定实际可用的授权调用路径、数据范围、成本与离线边界 | 产品验证阶段；不得推迟到 AI P1 |

每项 ADR（Architecture Decision Record）采用“背景、选项、决策、后果、状态、负责人、日期”记录。尚未作出决策时标记 `Proposed`，不可按 `Accepted` 实施跨模块契约。

## 7. 文档状态规则

需求状态统一为 `Proposed`、`Accepted`、`In Progress`、`Verified`、`Deferred`。标为 `Verified` 时附实现位置、验证命令/步骤、结果和目标版本；设计稿、静态 Schema 和概念图不构成实现证明。需求变化同步更新路线图、相关 Schema 与验收用例。

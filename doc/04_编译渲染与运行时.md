# 04 编译、执行与 GPU Runtime

> 状态：目标架构草案。后端选择、优化器与支持的效果类型应随阶段逐项实现和测量；见[项目执行与技术美术规范](09_项目执行与技术美术规范.md)。

## 后端职责

**CPU Reference Runtime：** 为纯函数节点和可重复计算提供语义基准、单元测试与调试路径。每个节点需声明 CPU 支持和确定性；尚未实现的节点应返回明确诊断，不可静默地产生默认值。

**GPU Runtime（阶段决策）：** 拟使用 wgpu 与 WGSL。仅当目标平台确认并有代表性场景的性能数据后纳入交付。GPU 资源由 Render Host 管理，节点只声明资源需求，不直接持有 Device 对象。CPU/GPU 差异按数据类型和效果约定容差；离散事件、排序及随机数序列须单独定义一致性语义。

## 执行管线

Graph JSON → Schema/Reference Validation → Socket Type Check → 普通 DAG 环路检查 / Simulation Zone 反馈检查 → Graph IR → 可选优化 → 后端能力检查与选择 → Schedule/Dispatch → Runtime → Result + Diagnostics。

每一步均应返回可定位到 Graph/Node/Socket 的稳定错误码与上下文。调试模式应能检查优化前后的 IR；运行时失败不得提交不完整结果。

## 优化策略

Constant Folding、Dead Node Elimination、公共子表达式复用、Kernel Fusion、Buffer Reuse、增量求值和预览 LOD 均为候选优化，不默认承诺 Async Compute 或 Tile Evaluation。优化必须由基准场景证明收益，并通过视觉/数值回归；调试模式可关闭优化。优化器需要保留节点来源映射，以便诊断和性能剖析回溯到用户图。

## 渲染与色彩

首个垂直切片按 ADR-0001 固定为引擎无关 PNG 序列与 Sprite Sheet + Atlas JSON；先验证 Sprite/粒子、Alpha、纹理过滤、颜色空间、排序。P0 以 CPU Reference 产出可显示/导出的帧，wgpu 是经 Windows Spike 评估的可选预览后端，不是首发硬依赖。Alpha Over、Add 等混合模式及 Mask、Gradient、Texture、Glow、Blur、Distortion、Mesh Rendering 按效果需求逐个排期。Straight/Premultiplied Alpha 和颜色空间写入工程/导出契约。

## 预览质量

Draft、Preview、Final 是质量档位定义，不隐含所有档位都已实现。Draft 可降低分辨率/粒子预算；Preview 面向交互；Final 采用目标导出质量。UI 应展示当前档位、降级项和模拟缓存状态；定量帧时间预算由首发设备基线确定。

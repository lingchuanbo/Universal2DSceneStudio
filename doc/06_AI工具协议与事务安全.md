# 06 AI Tool API、MCP 与事务安全
## Tool Registry
内置 Agent、外部 AI、脚本和未来 MCP Server 共用同一套 Tool Registry。工具必须版本化、有输入/输出 Schema、权限、超时、取消和审计记录。读写分离；写操作必须携带 Project Revision。

## Tool API 分期
首个可用版本必须实现完成基础 AI 创建/修改闭环所需的只读项目/图/选择/诊断查询，以及受限 Patch 创建、校验、预览、Apply 和 Undo；写操作带 expected_revision 且调用现有事务服务。Runtime Bake、多 Provider 管理、MCP 和批处理工具依赖相应功能阶段，不属于基础 AI 编辑闭环。双模工作流和验收见[文档 11](11_手动与AI双模编辑规格.md)。
**Project：** `project.get_summary`、`project.get_revision`、`project.list_assets`、`project.get_selection`  
**Graph Read：** `graph.get_summary`、`graph.get_node`、`graph.list_nodes`、`graph.get_connections`、`graph.get_diagnostics`、`graph.get_execution_stats`  
**Catalog：** `catalog.search_nodes`、`catalog.get_node_descriptor`、`catalog.list_node_groups`、`catalog.get_preset`  
**Graph Write（P0）：** `graph.create_preview_patch`、`graph.validate_patch`、`graph.apply_patch`、`graph.undo_transaction`。Patch 使用 `graph-patch.schema.json` 的受控操作，包含 expected_revision/read_set/write_set；事务服务负责冲突检查、权限、原子提交、Revision 递增和 Undo。AI Apply 不得以回滚方式覆盖后续人工历史。  
**Runtime：** `runtime.compile_graph`、`runtime.preview`、`runtime.get_render_result`、`runtime.get_simulation_status`、`runtime.bake_simulation`  
**Export：** `export.get_profiles`、`export.preview_settings`、`export.run`

## MCP 接入
先实现内部 Tool Registry，再提供 MCP Adapter。MCP 不直接访问 Rust 内部对象，只经本地 IPC/RPC 调用 Tool Host。Local MCP Server 默认关闭，用户主动启用并配置认证。API 使用 `/v1/` 版本空间。

## 事务流程
Read Revision → Build Patch → Validate → Preview Transaction → Compile/Render Preview → Approval → Apply → Commit New Revision → Undo Handle。Apply 原子提交，全部成功或全部失败。

## 风险与权限
P0 首版所有 AI 写入均先预览并由用户明确确认，包括低风险参数修改；自动应用不属于首版。后续版本若加入低风险自动应用，必须由用户在项目级显式授权、可随时撤销授权并提供清晰 Activity/Undo。删除、覆盖、批量修改、清理缓存、执行脚本等高风险操作始终确认。限制单次 Patch 节点数、对象数和资源预算。禁止默认 Shell/任意文件访问。记录 AI Activity Log，支持一键撤销最近一次 AI 事务。

## 错误码
NOT_FOUND、INVALID_ARGUMENT、TYPE_MISMATCH、REVISION_CONFLICT、PERMISSION_DENIED、VALIDATION_FAILED、COMPILE_FAILED、RUNTIME_FAILED、RESOURCE_LIMIT、CANCELED、INTERNAL_ERROR。

## 用户控制档位
- 建议模式：只生成计划和 Patch，不修改工程。
- 协作模式（P0 默认且首版唯一写入模式）：生成预览，用户明确确认后应用。
- 自动化模式：后续阶段候选；项目级显式授权低风险操作，高风险仍逐项确认。
